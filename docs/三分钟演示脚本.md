# 《改稿有账》三分钟演示脚本

参赛者：徐东  
演示准备：使用规则演示模式，清楚展示模式标识；所有聊天均为合成案例。点击右上“演示案例”载入一份新的示例，不影响已有项目。默认已有 V1 和五项候选变化，无需现场重建初始版本。提前打开作品并检查导出功能。

| 时间 | 页面操作 | 讲解词 |
|---|---|---|
| 0:00—0:20 | 停留在作品首页 | 大家好，我的作品是《改稿有账》，面向一个人接海报订单的设计师。客户说“顺便再加一个版本”时，我们常常要翻聊天，才能弄清原来答应了什么、现在又加了什么。这个作品把这些变化整理成能核对、能确认的记录。 |
| 0:20—0:45 | 切换“02 确认版本”，核对示例 V1 | 这里是一段合成订单：一张咖啡店开业海报，尺寸 1080×1920，10 月 22 日交付，预算 300 元，包含两轮修改。示例已保存 V1，我先展示这份需求基线。自己的订单可以从“整理需求”开始提取，再由人核对后保存。 |

## 现场检查

- 首页、设置及演示区应能明确区分规则演示与真实 AI。
- 演示仅使用合成数据，不出现真实客户身份、聊天账号或密钥。
- 至少展示一次原文证据、一次人工确认、一次待确认保留和一次导出。
- 若现场真实 API 不可用，继续使用已标示的规则演示，不冒充在线模型结果。
- 不说“客户已同意”“合同已生效”“已验证提效百分比”等未经验证的话。

## 30 秒备用版本

《改稿有账》帮助独立设计师管理海报订单需求。先把聊天整理成经用户确认的需求版本，再将新消息与这个版本比较，显示新增或改变的内容及对应原话。询问和缺失项先保留，设计师决定接受、赠送、追问或拒绝，再按自设价目表和逐项人工报价计算费用、导出清单。当前提供可运行的规则演示和可配置的真实 AI 接口，真实用户与模型效果仍待验证。
