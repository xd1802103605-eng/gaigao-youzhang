# 改稿有账

**独立设计师的需求变更助手**  
参赛者：徐东  
参赛方向：OPC 个人创新赛道，个人参赛  
作品版本：1.2.0

## 一句话介绍

把海报接单聊天整理为经设计师确认的需求版本；后续消息与该版本逐项比较，展示变化及对应原话，帮助设计师确认交付范围、沟通修改和形成清单。

## 面向谁，解决什么问题

本作品首先面向独立承接海报订单的设计师。一个人同时负责沟通、设计、排期和交付时，原先的约定与后来追加的要求容易混在一起。客户说“顺便再做个横版”时，设计师需要先弄清是否新增交付、尺寸是否齐全、交期是否改变，再决定如何处理。

本项目提出的待验证假设是：这类设计师需要一份能追溯聊天原话、持续更新的需求记录。作品尚未完成真实用户需求验证；目前场景、聊天和订单均为合成示例，不能据此宣称市场规模、付费意愿或实际提效比例。

## 核心使用流程

1. **录入初始聊天。** 粘贴已获使用许可并完成脱敏的文本，提取交付物、尺寸、数量、交期、修改轮次等信息。
2. **确认需求基线。** 用户检查提取结果，补齐缺失内容，再保存为已确认版本。未明确的内容保持“待确认”。
3. **比较后续消息。** 输入新的客户消息，与当前确认版本逐项比较，展示新增、修改、疑问或缺失，并保留原话供核对。
4. **由设计师决定。** 选择接受、赠送、追问或拒绝。询问不会自动成为已接受的要求；未约定的源文件也不会自动被视为应交付内容。
5. **计算与导出。** 按用户自设价目表及逐项人工报价计算费用参考，生成需求变更确认单和沟通草稿，并保留项目版本。

示例：“主海报不用动，能不能顺便加一张公众号横图，明晚给我？”应拆成主海报保持、横图新增请求、横图尺寸缺失、相对交期待确认。系统展示证据，由设计师决定接不接、何时交和是否收费。

## 当前作品范围

- 聚焦海报设计订单和手动粘贴的中文文本。
- 提供无需密钥的规则演示模式，用合成案例展示完整交互流程。
- 支持将需求版本和处理结果保存在本地浏览器；浏览器清理数据、隐私模式或更换设备可能导致记录不可用，重要内容应及时导出。
- 提供 OpenAI 兼容接口配置入口，可接入使用者拥有访问权限的 DeepSeek、Qwen 模型服务。实际兼容性取决于服务的接口、模型、网络和账户权限。
- 制作方未使用真实密钥完成供应商连通与效果验证；真实 AI 接入需要使用者在本机测试。开发检查采用模拟模型响应，不据此宣称真实模型准确率。

演示模式采用规则提取和预设逻辑，作用是展示产品流程，不能用它的表现证明大模型识别准确率。演示状态应始终清楚标示。

## 产品特色与赛道适配

OPC 的个人工作场景里，交付之外的沟通和管理也占用时间。本作品把“一个人接单时如何维护交付范围”作为小切口，将 AI 用于个人业务流程。

与通用聊天摘要相比，本作品围绕持续订单展开：先有用户确认的版本，再比较新消息；每条候选变化关联原文；询问、否定和未确认事项保留状态；确认后才形成新的交付记录。特色在于这条可检查的工作流程，不宣称全球首创。

作品与培训中“明确目标与标准”“保存上下文”“生成后检查”的方法呼应。培训内容用于产品启发，不代替赛事规则。赛道资格、最终提交内容与时间应以官方最新公告为准，参考[官方赛道页面](https://wuhan.uoyc.com/1024/hackathon/)及[日程页面](https://wuhan.uoyc.com/1024/schedule/)。

## 技术架构

```text
本地网页（HTML / CSS / JavaScript）
  ├─ 项目表单、原文证据、人工确认、价目表、导出
  ├─ 浏览器本地项目记录
  ├─ 规则演示模式
  └─ 真实 AI 模式 → 本地 Node.js HTTP 服务 → 用户配置的模型 API
```

服务使用 Node.js 20 或更高版本的内置能力，不依赖 npm 安装。前端负责交互和本地记录，服务端提供静态页面并转发 AI 请求。密钥仅在当前页面内存中保留，服务不持久化保存密钥；请求处理中密钥会经过本地服务并发送给所配置的模型服务。关闭或刷新页面后需要重新填写。

真实 AI 模式可能把输入的聊天和需求记录发送至用户配置的模型服务。应先取得资料使用许可、去除联系方式及其他无关个人信息，并核对服务商的隐私政策、收费和数据处理条款。请在自己的设备和可信环境中使用，不要将本地服务直接暴露到公网。

## 运行方法

1. 直接双击根目录 `双击体验.html` 可使用离线规则版；真实 AI 推荐安装 Node.js 20 或更高版本（本次在 24 验证）。
2. 双击项目根目录中的 **启动作品.cmd**，按启动窗口提示打开本地页面。
3. 先进入演示，走完“初始需求—确认版本—新增消息—人工决定—导出确认单”。
4. 如需真实 AI，在设置中选择供应商、填写模型名称和自己的密钥，先点击“测试连接”，保存设置后再分析合成或脱敏样本。DeepSeek 默认 `deepseek-flash`，千问默认 `qwen-plus`；千问使用北京地域，可选填北京子业务空间 ID。

具体端口、启动方式及页面入口以项目根目录的运行说明为准。本项目不需要先注册产品账户；配置模型服务可能需要服务商账户及相关费用。

## 检验方式

产品检验分为两层：开发者检查可复现的合成案例；再邀请有接单经历的人完成匿名真实任务。完整安排见[评测方案.md](评测方案.md)，真实记录模板见[评测方案与记录.csv](评测方案与记录.csv)。

评测将对比手工整理、通用聊天提示词和本作品三种方法，记录漏项、误报、用时、人工修订，以及最终确认单是否准确。相对日期、不确定措辞、否定和恶意指令是重点检查项。未执行的测试不填写结果，不能把计划写成已经获得的成绩。

## 边界与后续工作

- 提取和比较结果是候选结论，必须对照原文核对。当前规则和模型都可能漏判、误判，跨多轮指代及复杂组合要求尤其需要检查。
- “明晚”等相对时间需要结合消息时间与时区确认；缺少时间依据时应保留原话并追问。
- 报价来自用户自己的价目表和逐项人工报价，模型不估价。横图可沿用横图费率，其他新增交付必须手填金额或明确赠送；未定价的收费项不能保存。赠送和收费逐项独立，系统不能代表客户已接受费用。
- 导出清单用于沟通和留存，作品不承诺法律效力，也不自动替代合同、付款或客户确认。
- 真实需求验证、真实模型准确性评测、跨设备同步和商业收费均尚待后续完成。
